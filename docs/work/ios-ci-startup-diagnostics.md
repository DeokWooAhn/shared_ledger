# iOS CI 시작 실패와 진단 수집

- 목표: 머지 후 워밍업에서 홈 로딩이 끝나지 않는 원인을 재현·수정하고, Firebase·앱·시뮬레이터 진단을 보관한다.
- 범위: 테스트 전용 시작점, iOS Maestro 실행·진단 스크립트와 CI, 필요한 회귀 검사와 안내. 운영 Firebase·계산 규칙·보안 규칙은 유지한다.
- 검증: 실패 기록의 로그인 이후 데이터 구독 경로를 확인하고 iOS smoke를 두 번 실행한다. Flutter 포맷·분석·테스트와 진단 스크립트 검사를 거쳐 작업 브랜치·PR·머지 후 CI를 확인한다.
- 완료: CI·리뷰 확인 후 PR 머지, 기본 브랜치 CI 확인·로컬 최신화·작업 브랜치 정리.
- 근거: 진단 실행 43577250548에서 첫 가계부 구독은 09:08:19 → 09:08:43, 홈 요약은 09:08:50에 완료됐다. 화면 대기는 09:08:10부터 약 31초여서 데이터가 오기 전에 실패했다. 오류·크래시가 아니라 CI의 첫 읽기 지연이다.
- 추가 근거: 실행 43583777337은 호스트의 인증 REST 읽기가 1초 안에 준비됐어도 앱 시작·구독에 약 40초가 걸렸다. 서버 사전 읽기만으로 기기 콜드스타트를 해결할 수 없어 그 준비 코드는 제거한다.
- 수정: iOS 앱 시작은 60초 예산으로 앱·SDK 초기화를 기다린다. Android는 기존 30초이며 화면 금액·서버 필드 단언은 유지한다.
- 드라이버 근거: 실행 43586324615는 워밍업 통과 뒤 두 번째 CLI의 XCTest 준비가 끝났다고 기록됐으나, 첫 `stopApp`부터 7001 포트 연결이 끊겼다. 별도 iOS 워밍업 CLI를 제거하고 세 Flow를 한 호출로 실행한다.
- 후속 확인: 실행 43580102208에서 워밍업·탭 이동·휴지통은 통과했다. 추가 검증은 낙관적 화면 반영 후 서버를 1초 미만 동안 4번 조회하고 실패했다. 서버 응답 전에 끝나는 새 항목 추가의 약속에 맞춰 화면 합계와 서버 결과를 함께 확인하는 읽기 반복으로 바꾼다. 입력값과 목록 제목도 저장 전후에 확인해 입력 문제를 구분한다.
- 로컬 확인: iOS 26.5·27의 3개 Flow, Flutter 포맷·분석·테스트 762개 통과. 서버 반영 대기도 두 시뮬레이터에서 연속 통과했다. 최종 단일 CLI의 3개 Flow와 회귀 검사 25개가 통과했다. CI·리뷰·머지 확인은 PR에 연결된 실행 결과를 따른다.
