# 항목 추가 입력 흐름 다듬기

- **목표:** 항목 추가 화면을 덜 번거롭게 한다. 사용자 요청 8가지(2026-11-24).
  1. + 버튼은 칸의 첫 번째 종류(고정 수입·고정 지출)로 연다. 지금은 두 번째(추가 수입·추가 지출)다.
  2. 금액 칸은 줄 전체를 눌러도 키보드가 뜬다. 지금은 초점이 남은 채 키보드만 내려가 있으면 숫자 부분만 눌린다.
  3. 금액에서 완료(다음)를 누르면 내용 칸으로 간다. 내용에서 완료하면 키보드를 닫는다(다음 칸이 고르는 칸).
  4. 누가는 나로 시작한다. 코드는 이미 로그인한 사람의 자리(`Ledger.slotOf`)로 고른다 → 테스트로 확인하고, 기기에서 다르게 나오면 원인을 따로 찾는다.
  5. 새 항목 화면 제목은 칸 이름으로: 수입 추가·지출 추가·카드 지출 추가. 고치기 제목은 그대로.
  6. '카드 대금'을 '카드 지출'로 바꾼다. 화면 문구·변경 기록 요약·주석·문서. 식별자(`cardBill`, `cardBills`)와 Firestore는 그대로.
  7. 입력 중에 아래 칸을 누르거나 스크롤하면 키보드를 닫고 화면은 그 자리에 둔다(입력란으로 되돌아가지 않는다).
  8. 고정 수입·추가 수입의 받은 날은 전달 1일부터 고를 수 있다(11월 월급을 10/25에 받음). 계산 달은 그대로 항목의 달이다.
- **수정 범위**
  - 앱: `core/providers/providers.dart`(addKind), `core/widget/form_parts.dart`(금액 칸), `core/widget/entry_kind_label.dart`,
    `feature/entries/entry_form_screen.dart`(제목·다음 칸·키보드 닫기·날짜 범위), 카드 대금 문구가 있는 feature·domain 파일
  - 테스트: + 버튼이 추가 지출로 연다고 가정한 위젯 테스트, 카드 대금 문구 테스트, 새 동작 테스트
  - Maestro: `02_entry_save_edit.yaml`은 + 뒤 종류를 추가 지출로 고르는 단계를 더한다(종류 칸에 접근성 식별자 추가)
  - 문서·디자인: `docs/plan.md`·`docs/firestore.md`·스킬의 카드 대금, 날짜 범위 결정. `design/app.pen`의 '카드 대금'·'항목 추가' 문구와 PNG
  - 제외: 계산 규칙, Firestore 규칙·필드·Functions, 반복 설정의 '전달 예정일'(받기 전 예정일은 그달 그대로), 달력 화면을 고쳐서 전달 날짜를 보여주는 일
- **검증:** 바뀐 동작마다 위젯 테스트. `fvm dart format --output=none --set-exit-if-changed lib test testing`, `fvm flutter analyze`, `fvm flutter test`.
  기기가 연결되면 실기기에서 금액 칸 누르기·다음 칸·키보드 닫기·누가 기본값을 확인한다. Maestro는 CI에서 돈다.
- **완료 조건:** 위 검사 통과, PR CI 통과.
- **불확실한 점**
  - 4번: 지난번 기기에서 누가가 '민지'로 골라진 이유. 로그인한 계정이 민지 자리면 정상이다. 기기 연결 후 설정 화면의 '(나)'로 확인한다.
  - 3번: iOS 숫자 키패드에는 완료 키가 없어 iOS에서는 다음 칸 이동이 동작하지 않는다.
  - 8번: 전달 날짜로 받은 항목은 그달 달력에 놓이지 않고 '날짜 없는 항목'으로 센다(달력은 그달 날짜만 그린다).
  - 달력에서 날짜를 눌러 여는 입력은 그날 쓴 돈이라 지금처럼 추가 지출로 연다.

  - 실기기가 연결되지 않아 4번(누가 기본값)과 금액 칸·키보드 동작은 기기에서 보지 못했다.
