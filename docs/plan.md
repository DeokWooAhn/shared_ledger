# 심플 공유 가계부 계획

커플·부부가 함께 쓰는 가계부. 구글 시트로 쓰던 공동 가계부를 앱으로 만들어 일반 사용자에게 공개 배포한다.

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 대상 | 커플·부부 (두 사람이 함께 쓰는 가계부) | 2026-10-21 결정. 한 가계부에 두 명까지(보안 규칙으로 막음). Firestore 컬렉션 이름도 `ledgers`로 바꿨다 |
| 앱 이름 | 심플 공유 가계부 | '심플 환율 계산기'와 같은 '심플' 시리즈. 같은 이름의 앱이 App Store에 없음(2026-10-21 확인) |
| 번들 ID | Android `com.ahn.sharedledger`, iOS `com.ahn.SharedLedger` | CalcMoney(`com.ahn.calcmoney` / `com.ahn.CalcMoney`)와 같은 규칙. 출시 후에는 바꿀 수 없다 |
| 앱 | Flutter | 카카오·광고 공식 SDK, 데스크톱·웹까지 성숙한 생태계 |
| 서버 | Firebase `simple-shared-ledger`, Blaze(종량제) | 쓰지 않으면 멈추는 일·백업 걱정이 없고, 오프라인 쓰기 대기가 기본 제공. **고정 월 요금 유료 플랜은 쓰지 않는다** |
| 첫 출시 | Android, iOS 15.0 이상(아이폰·아이패드) | Mac은 아이패드 앱이 Apple Silicon Mac에서 그대로 실행. iOS 15는 Firebase가 요구하는 최소 버전 |
| Windows | 출시 후 웹 버전으로 | 데스크톱용 Firebase SDK는 개발용(베타)으로 안내됨 |
| 오프라인 | 보기 + 새 항목 추가만 | 공동 가계부라 수정 충돌을 피함. 수정·삭제는 온라인에서만 |
| 폴더 구조 | `lib/core` + `lib/feature/<기능>` | feature끼리는 서로 import하지 않고, 같이 쓰는 건 core로 |
| 화면 구조 | MVVM: View 위젯 + Riverpod `Notifier` 컨트롤러(불변 State) | 2026-10-21 결정. Bloc은 Riverpod과 상태관리가 겹쳐 쓰지 않음. CalcMoney MVI와 같은 단방향 흐름 |
| 이름표 | 가계부마다 두 장(`owner`·`partner`). 항목의 '누가'는 이 자리로 적는다 | 2026-10-22 결정. 상대가 들어오기 전에도 상대 몫을 적을 수 있다. 이름은 설정에서 바꾼다 |
| 기본 분류·결제수단 | 분류는 시트와 같은 4개(대출원금·대출이자·저축/투자·소비), 결제수단은 공동 통장·자동이체 | 2026-10-22 결정. 가계부를 만들 때 같이 넣는다. 카드는 사람마다 달라 직접 추가한다 |
| 달 기준 | 달력 1일~말일 | 2026-10-22 결정. 시트와 같다. 월급날 기준 달은 쓰지 않는다 |
| 권한 | 역할 3개: 관리자(owner, 가계부를 만든 사람)·편집자(editor)·보기 전용(viewer) | 기본은 모두 편집자. 승인 방식 대신 변경 기록 + 휴지통으로 신뢰 확보 |
| 인앱 결제 | 넣지 않음 (수익 모델을 유료 기능으로 정할 때만) | 스토어 수수료·구독 관리 부담 |
| 작업 방식 | 브랜치 + PR, CI 통과 후 squash merge, 커밋은 한국어 문장 | CalcMoney와 같은 방식. 규칙은 AGENTS.md |
| 라이선스 | 모든 권리 보유 (소스 열람만 공개) | CalcMoney와 같음 |

## 계산 규칙 (`lib/core/budget`)

기존 시트 수식을 그대로 옮겼다. 처음에는 실제 시트 10·11월 숫자로 같은 값이 나오는 것을 확인했고(2026-10-20), 공개 저장소로 바꾸면서 `test/core/budget/sheet_golden_test.dart`의 데이터는 시트와 같은 구성에 금액만 가상으로 넣은 것으로 바꿨다.

| 지표 | 정의 |
|---|---|
| 현금 유입 | 수입 합계 |
| 이번 달 지출 | 기본 월 지출 전체 + 추가지출 전체 (결제수단 상관없음) |
| 현금 유출 | 카드가 아니면서 지급된 기본 지출 + 카드가 아닌 추가지출 + 카드대금 |
| 저축 | '저축으로 집계'가 켜진 분류의 기본 지출 |
| 남는 현금 | 현금 유입 − 현금 유출 |
| 카드 이번 달 사용분 | 카드로 낸 기본 지출 + 추가지출 (지급일 상관없음, 다음 달 청구 예정) |
| 카드 저번 달 사용분 | 카드대금 합계 (이번 달 출금) |
| 기본 월 지출 소계 | 분류별, 구성원별 합계 |

시트와 달라지는 점:
- 저축 대상 분류를 이름으로 고정하지 않고 분류마다 '저축으로 집계'를 켜고 끈다.
- 결제수단을 카드별로 고를 수 있어서 카드별 다음 달 청구 예정액도 나온다.
- 시트는 '지급일' 칸 하나가 예정일과 지급 완료를 같이 뜻해서, 미리 날짜를 적으면 아직 안 빠져나간 돈도 현금 유출에 들어간다. 앱에서는 고정 지출 템플릿에 **예정일**을 두고, 그 달 항목에는 **지급 완료(paidOn)** 를 따로 둔다.

## 데이터 구조 (Firestore)

데이터베이스는 `(default)`, 위치 asia-northeast3(서울), Native 모드, Standard 에디션, 삭제 보호 켬(2026-10-21 생성).

컬렉션 구조, 필드, 역할별 권한은 [firestore.md](firestore.md)에 정리했다. 요점만:

- 가계부 문서에 관리자(`ownerUid`)와 나머지 구성원의 역할(`roles`: 편집자·보기 전용)을 따로 둔다. 규칙 언어로는 '관리자가 한 명뿐인지'를 셀 수 없어서 이렇게 나눴다.
- '내 가계부 목록'은 가계부 문서의 `memberUids`로 조회한다. 처음 계획한 `users/{uid}` 문서는 쓰지 않는다.
- 구성원은 초대 코드(7일 유효)로만 들어온다.
- 모든 항목에 `createdBy`·`createdAt`·`updatedBy`·`updatedAt`을 남기고, 휴지통(`deletedAt`)에 있는 항목만 완전히 지울 수 있다. 휴지통 항목은 합계에서 뺀다.
- 가계부를 만들 때 이름표 두 장과 기본 분류·결제수단을 같은 일괄 쓰기로 넣는다.
- 규칙 테스트 37개(`firestore-tests/`)가 에뮬레이터에서 통과한다. 규칙을 바꾼 PR은 합쳐진 뒤 운영에 배포한다(firebase 스킬).

## 화면 (첫 출시)

1. 로그인
2. 가계부 시작: 새로 만들기 / 초대 코드로 참여
3. 월 요약: 상단 지표, 카드 소계, 기본 월 지출 소계
4. 항목 목록: 수입 / 기본 월 지출 / 추가지출 / 카드대금
5. 항목 입력·수정
6. 고정 지출 관리 (템플릿)
7. 설정: 구성원·역할, 분류, 결제수단·카드, 계정(로그아웃·탈퇴)

월 요약·항목·고정 지출·설정(3~7)은 아래 탭 4개로 오간다. 요약과 항목 탭은 같은 달을 본다.
아이패드·Mac용 넓은 화면 배치(왼쪽 목록 + 오른쪽 요약)를 처음부터 같이 만든다. 폭 600 이상에서는 탭 막대가 왼쪽으로 간다.

## 출시 요건과 비용

- 앱 안 계정 삭제(두 스토어 필수, Play는 웹 삭제 요청 링크도), 개인정보처리방침 URL(Firebase Hosting), App Store 개인정보 라벨, Play 데이터 보안 양식.
- iOS에서 구글·카카오 로그인을 넣으면 Apple 로그인도 함께 제공한다.
- Blaze도 무료 할당량(Firestore 읽기 하루 5만 건 등) 안에서는 0원. 백업은 Firestore 예약 백업.
- 비용 관리는 Google Cloud 결제의 'Budgets & caps'에서 이 프로젝트만 범위로 잡아 설정한다.
  - 예산 알림: 메일만 보낸다.
  - 지출 한도(cap): 넘으면 그 서비스를 일시중지하고 매월 초에 자동으로 풀린다. 프로젝트 1개·서비스 1개 범위로만 만들 수 있다.
    - **Firestore는 대상이 아니다**(2026-10-21 문서 확인). 그래서 Firestore 비용은 알림 예산과 App Check·보안 규칙·읽기 횟수 관리로 막는다.
    - Cloud Functions는 대상이다. 카카오 로그인 함수를 만들 때 Functions 한도 예산을 따로 추가한다. 출시 전에는 낮게, 출시 후에는 로그인이 멈추지 않을 만큼 높게 둔다.
  - 지금은 '알림만' 예산(₩5,000) 하나가 있다.
- CalcMoney와 같은 결제 계정을 쓴다. 기존 'CalcMoney Firebase 예산'은 범위가 결제 계정 전체라 두 앱 비용이 합쳐서 잡힌다.
