# 코드 리뷰

이 파일에는 이 저장소에만 해당하는 기준을 둔다. 일반적인 Flutter·Dart 리뷰 기준은 따로 적지 않는다.

## 대상 범위

- 기본은 `git diff origin/main...HEAD`. PR이면 `gh pr diff <번호>`.
- 바뀐 코드와 그 코드가 직접 깨뜨릴 수 있는 곳만 본다.

## 지적하지 않을 것

- 포맷·import 순서·린트. CI의 `dart format`과 `flutter analyze`가 막는다.
- 바뀌지 않은 기존 코드의 리팩터링.
- 지금 코드와 동등한 다른 방식(이름, 위젯 구성, 문법 취향). 이 저장소의 규칙을 어긴 게 아니면 넘어간다.
- 생성 파일(`lib/firebase_options.dart`)과 lock 파일의 버전 숫자. 단, 아래 '실제로 겪은 일 1'의 흔적은 본다.

## 심각도

| 단계 | 기준 | 예 |
| --- | --- | --- |
| 반드시 고침 | 그대로 합치면 사용자가 피해를 보거나 빌드·배포가 깨진다 | 권한 우회, 실제 Firestore 쓰기 거부, 데이터 손실, 개인정보 노출, 잘못된 합계, 빌드 실패 |
| 고치면 좋음 | 지금은 동작하지만 다음 변경에서 깨지기 쉽다 | 테스트 빠짐, 가짜 저장소 누락, 불필요한 Firestore 읽기 |
| 질문 | 의도에 따라 맞을 수도 틀릴 수도 있다 | 규칙 넓히기, 계산 정답 숫자 변경, 패키지 세대 변경 |

## 실제로 겪은 일

모두 2026-10-21에 있었다. 같은 모양이 diff에 보이면 지적한다.

1. **다른 Flutter 버전으로 실행한 흔적.** Android Studio가 전역 Flutter 3.35.5로 실행해 `pubspec.lock`의 `sdks`가 내려가고
   패키지 버전이 섞였으며, `ios/Flutter/*.xcconfig`에 Pods 줄이 생기고 `ios/Podfile`이 생겼다. → 반드시 고침
2. **Firebase 패키지 세대를 올려 iOS 빌드가 깨짐.** firebase_core 5와 google_sign_in_ios의 iOS 의존성이 충돌했다.
   `pubspec.yaml`에서 Firebase 패키지 세대가 바뀌면 iOS 빌드를 확인했는지 묻는다(firebase 스킬). → 질문
3. **공개 저장소에 실제 데이터.** 공개 전에 테스트 픽스처의 실제 시트 금액을 가상 금액으로 바꿨다.
   테스트·문서·주석에 실제 금액·이름·이메일·uid가 들어오면 → 반드시 고침
4. **플랫폼 분기 테스트가 다른 테스트까지 깨뜨림.** `debugDefaultTargetPlatformOverride`를 직접 바꿨더니 const 위젯이 다시 그려지지 않아
   연달아 실패했다. `TargetPlatformVariant`를 쓰는지 본다(verification 스킬의 테스트 작성 기준). → 고치면 좋음
5. **`flutterfire configure`가 `firebase.json`을 한 줄로 압축함.** diff에서 `firebase.json`이 통째로 한 줄이 되면 펼쳐 달라고 한다. → 고치면 좋음

## 깨지기 쉬운 약속

아직 사고는 없지만, 한쪽만 바꾸면 테스트는 통과하고 실제로는 깨지는 곳이다.

- **앱이 쓰는 필드 = 보안 규칙이 받는 필드.** 앱 테스트는 가짜 저장소로 돌아서, 규칙이 받지 않는 필드가 하나만 있어도 실제 쓰기 거부를 못 잡는다.
  쓰기 데이터나 규칙을 바꿨으면 new-feature 스킬의 'Firestore 필드·컬렉션을 바꿀 때' 목록이 같이 바뀌었는지 본다. → 반드시 고침
- **권한 판단이 두 곳에 있다.** `firestore.rules`와 `lib/core/model/ledger.dart`(두 명 제한 포함). 한쪽만 바뀌면 → 반드시 고침
- **감사 필드는 서버 시간이다**(`docs/firestore.md`). 기기 시간(`DateTime.now()`)을 쓰면 규칙이 거부한다.
  방금 쓴 문서는 서버 시간이 아직 null이라 정렬·표시에서 처리하는지 본다. → 반드시 고침
- **휴지통 항목은 합계에서 뺀다**(`docs/plan.md`). 합계·목록 쿼리를 바꿨으면 `deletedAt` 처리를 본다. → 반드시 고침
- **화면 이동은 `redirectFor`가 정한다.** `AppGate`를 바꿨으면 `test/router_test.dart`에 그 경우가 있는지 본다. → 고치면 좋음
- **Firestore 읽기는 곧 비용이다.** Firestore는 지출 한도 대상이 아니다. 컬렉션 전체 구독이나 같은 쿼리 중복 구독은 → 고치면 좋음
- **CI는 `.fvmrc`의 버전과 `--enforce-lockfile`에 기댄다.** 워크플로에서 Flutter 버전을 하드코딩하거나 lock 확인을 빼면 → 반드시 고침

## 저장소 규칙

AGENTS.md의 '구조'·'지금 쓰지 않는 것'·'보안·공개 저장소'를 어긴 곳을 찾는다. 규칙 문장은 거기가 원본이라 여기 옮겨 적지 않는다.
보안 규칙을 넓히는 변경은 이유를 묻고(→ 질문), 바뀐 규칙마다 허용·거부 테스트가 둘 다 있는지 본다.
